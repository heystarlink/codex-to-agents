# Codex to Agents

**让 Codex 指挥 agents 干活。**

> **已经 clone 安装过？** 旧版需要先[手动升级一次](docs/upgrading.md)。升级后，打开 Agents 看板会每天最多自动检查一次更新，有新版时在「插件更新」提示；也可在这里开启默认关闭的「自动更新」。

在 Codex 里提需求，把具体工作交给 **Hermes**、**DeepSeek Harness（DSH）** 或 **Qoder CLI（Qoder）**，再回到同一个会话查看进度、继续追问、验收产物。

你控制派工开关和执行端，Codex 负责拆解与验收，Agent 负责实际执行。需要派工时，在 Codex 左侧的 **Agents 看板**打开开关；关闭后，继续按原来的方式使用 Codex。

> 「SOL 规划、DSH、Hermes 或 Qoder 实现代码」这种模式的实际效果**暂未验证**。

## 它帮你完成什么

当你已经在使用 Codex 和另一个 Agent 时，可以把需求下发、进度跟踪和结果回传接起来，减少在工具之间复制粘贴。

| 你要做的事 | 使用方式 |
|---|---|
| 把明确的编程任务交给 Agent | 在 Codex 说明目标、目录和验收条件，由它派发任务 |
| 随时决定是否派工 | 在看板切换「自动派工」，选择 Hermes、DSH 或 Qoder 及其可用模型和思考强度；三个执行端还可分别设置各自的新会话权限 |
| 知道任务卡在哪里 | 在 Codex 查询任务进度、结果或对应的原生会话 |
| 接着已有任务修改 | 在 Codex 继续提要求，沿用原生 Agent 会话 |
| 检查交付是否可用 | Codex 读取结果，核对文件并运行相应验证 |

```mermaid
flowchart LR
    U[你：需求与决定] --> C[Codex：拆解与派工]
    C --> A[Hermes / DSH / Qoder：执行]
    A --> R[进度、文件与结果]
    R --> C
    C --> V[Codex 验收后向你交付]
```

讨论、方案比较和代码解释可以直接在 Codex 完成。需要实际写代码、修复问题或运行测试时，再打开派工。

## 分工与选型

### SOL 负责规划与验收

SOL 在 Codex 中承担主控角色，先把执行前的关键决策做清楚，再把具体工作交给执行 Agent。期望通过规划减少歧义与返工：

- **明确边界**：把需求转成具体目标、允许修改的范围和必须保留的行为。
- **降低执行难度**：给出实现步骤、异常场景和验收条件，让执行端少猜业务含义。
- **协调跨模块修改**：先确定接口、数据约定和修改顺序，减少各自实现造成的冲突。
- **持续检查交付**：保留需求上下文，核对文件和运行结果，再安排必要修复。

例如“加一个取消按钮”，规划阶段先明确取消当前任务还是连排队任务一起取消、如何确认停止，执行端据此实现。简单修改可以直接完成，是否派工由用户开关与具体任务决定。

### 执行端要快、量大、能力达标

执行端的选型目标是：**极致的快、量大管饱、中等偏上的实现能力。**

| 要求 | 具体看什么 |
|---|---|
| 快 | 启动、读代码、工具调用、修改和验证的完整交付时间 |
| 量大管饱 | 调用成本、可用额度、持续吞吐与并发稳定性 |
| 能力达标 | 理解明确方案、修改多个文件、正确使用工具，并根据测试结果自行修复 |

DSH、Hermes 与 Qoder 提供执行框架，实际速度、额度和代码能力还取决于接入的模型与提供方。

这套分工的目标是 **SOL 做少量关键决策，执行 Agent 高频交付合格代码**。衡量时看单位时间、单位成本完成的合格任务数；实际效果暂未验证。

## 安装与接入

### 1. 准备环境

本教程面向 macOS 本机桌面工作流。开始前需要：

- **Node.js 22.19+** 和 npm。
- **Codex 桌面端及 CLI**；桌面端需支持插件、MCP Apps 看板和插件 Hook。
- **Hermes Agent CN Desktop 或 DSH 桌面端**，至少一个已配置模型，且能在原生界面正常聊天；或 **Qoder CLI**（官方安装并已登录，见下文）。

模型账号和用量由执行端管理。首次使用自动派工，需要在 Codex 审核并信任插件 Hook；开关默认关闭。

```bash
git clone https://github.com/heystarlink/codex-to-agents.git
cd codex-to-agents
npm ci
mkdir -p "$HOME/codex-agents-demo"
```

下面的三条接入路线任选，也可以分别启用多个执行端。安装完成后请保留仓库目录和 Node 可执行文件，插件运行时会用到它们。

### 2. 连接执行端

**使用 Hermes**

先打开 Hermes，确认可以正常聊天，再在本仓库目录运行：

```bash
node src/command.mjs enable --executor hermes \
  --directory "$HOME/codex-agents-demo"
```

默认连接本机 `http://127.0.0.1:9120`，使用 Hermes 当前默认模型。其他端口和模型限制见[进阶配置](docs/advanced.md#配置执行端)。

**使用 DSH**

先打开 DSH。下面允许派工使用 DSH 中已加载的全部模型提供方，模型目录会随 DSH 配置更新：

```bash
node src/command.mjs enable --provider '*' \
  --directory "$HOME/codex-agents-demo"
```

命令会为 DSH 安装本地执行插件。若插件没有自动加载，重启 DSH。

需要限定派工使用的提供方时，将 `'*'` 换成实际 ID，例如 `deepseek-account`；多个 ID 用逗号分隔。看板仅显示允许范围内的模型。

**使用 Qoder CLI**

先安装官方 Qoder CLI 并完成登录。安装、登录和账号都由官方 CLI 管理；本项目不安装软件、不读取凭据：

```bash
curl -fsSL https://qoder.com/install | bash
qodercli login
qodercli --list-models   # 能看到 MODEL 表头和一列模型名即表示已登录、目录可用
```

再在本仓库运行：

```bash
node src/command.mjs enable --executor qoder \
  --qoder-executable "$HOME/.local/bin/qodercli" \
  --directory "$HOME/qoder-workspace"
```

`--qoder-executable` 可省略：会依次在 `PATH`、`~/.local/bin/qodercli`、`~/.qoder/entry/qoder` 和 `~/.qoder/bin/qodercli/qodercli` 中查找，并用 `--version` 校验。显式传入的路径只校验该文件，失败时不会静默换用其他 CLI。`--directory` 是默认任务目录，必须是绝对路径；成功后配置写入数据目录的 `settings.json`，可用 `disable --executor qoder` 关闭并保留历史工作单。

Qoder 看板的模型来自真实 `qodercli --list-models` 输出，当前版本是一列模型名；未安装、未登录或输出无法识别时，看板会显示具体原因而不是虚构模型。选择具体模型时新任务传 `--model`，不选择时跟随 CLI 默认且不传该参数。Qoder 的思考强度只在 CLI 模型目录声明了 `efforts` 时才可选；真实 1.1.78 目录没有声明，因此默认不传 `--reasoning-effort`。Qoder 有独立的「新会话权限」：看板通过真实 `qodercli --help` 确认 `--permission-mode` 的可用取值，跟随默认时不传该参数；显式选择时把原生 snake_case 值传给 CLI，并在 `system/init` 回报后归一化 alias 核对，不一致会终止并如实标记结果不确定。续聊沿用原任务记录的权限，不重新读取看板。

三条路线都会备份配置并注册派工连接；已有其他执行端的配置会保留。遇到 `codex` 命令找不到时，先看[如何指定 Codex CLI](#找不到-codex-命令怎么办)。

### 3. 安装 Agents 看板

```bash
node src/command.mjs plugin-install
```

安装后：

1. 重启 Codex，让客户端载入插件和连接配置。
2. 按 Codex 的提示审核并信任 **Agents 看板**的 `UserPromptSubmit` Hook，然后新建会话。
3. 从左侧打开 **Agents 看板**，选择刚接入的 **Hermes**、**DSH** 或 **Qoder**，再选择模型或跟随执行端默认；选择固定模型后可按目录提供的选项设置思考强度。三个执行端都可分别设置各自的新会话权限。
4. 打开 **自动派工**。设置保存后，从下一条消息生效。

看板集中设置派工开关、执行端、可用模型、思考强度和当前执行端的新会话权限；首次信任 Hook 后，日常切换无需重启，也无需每次重复说“调用 Agent”。具体是否派工仍由 Codex 结合任务和当前指令判断。

三个执行端各自保存自己的「新会话权限」，切换执行端不会丢失其他端的选择：DSH 可选跟随 DSH 默认、仅可查看、工作区内修改、完全权限；Hermes 可选跟随 Hermes 默认、跳过审批（会话级 YOLO）；Qoder 可选跟随 Qoder 默认、自动接受安全编辑、需确认即拒绝、由 Qoder 判断、跳过权限审批。权限只对之后新建的派工会话应用，已有会话和追问不重新读取看板。执行端未提供所选权限时，保存和派工都会明确失败，不会静默换成其他权限。

**开启后显示「待生效」时，先处理卡片中的 Hook 提示。** 在 Codex CLI 输入 `/hooks`，审核并信任 Agents 看板的 `UserPromptSubmit` Hook。看板会读取 Codex 的真实信任状态；保存开关不代表 Hook 已运行。首次安装或更改 Hook 后，旧会话需重新加载，已开始的任务不会中途自动转交。

## 第一次派工

先用一个可以直接核对结果的小任务走通流程。在已开启自动派工的 Codex 新会话中发送：

```text
在接入时配置的默认任务目录中创建 hello.js，运行后输出 Hello, World!。
只修改 hello.js。请交给所选 Agent 实现，完成后检查文件并实际运行验证，告诉我结果。
```

任务会经历三个阶段：

1. **Codex 安排工作**：检查所选执行端，限定任务范围并保存工作单。
2. **Agent 实际执行**：在 Hermes、DSH 或 Qoder 中创建原生会话，执行任务并回传进度。
3. **Codex 检查交付**：核对文件和运行结果，再向你报告完成情况。

完成后，你可以让 Codex 查询任务，在执行端查看原生聊天，也可以自己验证：

```bash
node "$HOME/codex-agents-demo/hello.js"
```

预期输出：

```text
Hello, World!
```

**「已提交」表示任务已保存；实际成功要看文件、执行输出和验收结果。** 如果任务持续执行中或失败，按[任务没有完成时怎么查](#任务没有完成时怎么查)检查。

接着在同一个 Codex 会话中发送：

```text
继续刚才的任务，把输出改为 Hello, Agents!，仍然只修改 hello.js，并重新运行验证。
```

Codex 可以把补充要求送到原来的 Agent 会话，保留已有上下文。

## 日常使用

### 自己决定什么时候派工

| 开关状态 | 后续行为 |
|---|---|
| 开启 | Codex 按所选执行端的派工偏好处理编程、修复和测试任务；问答与规划直接处理 |
| 关闭 | Codex 停止主动派发新任务，已提交的工作继续跟进 |
| 关闭，但你明确指定 Agent | 仍可以按你的明确要求调用该 Agent |

开关、执行端、模型和思考强度对**共用同一数据目录的 Codex 会话**生效。当前没有每个会话单独保存的开关。新任务使用所选模型和强度，已有任务和追问沿用原会话配置。切换模型或执行端会清除不兼容的思考强度；切换执行端后模型恢复为跟随该执行端默认，不会迁移已经提交的任务。

「新会话权限」按执行端分别保存，只在之后新建派工会话时应用一次；已有会话和追问不会被重新设置，也不会因为看板后续改动而改变已有任务的权限。跟随默认时不写入任何权限设置；选择具体权限时：

- DSH 通过原生 `permissionPresets` 映射到对应的沙箱与审批组合，并在第一条任务消息前读回确认。
- Hermes 通过原生 `config.set` 写会话级 YOLO（`scope=session`），只跳过该新会话的危险命令审批；不修改全局审批设置，也不提供文件系统沙箱。设置后尽力用 `session.info` 读回；等不到事件时以 setter 返回的 scope/value 确认，并如实标注读回方式。
- Qoder 通过真实 `--permission-mode` 传参；CLI 在写 stdin 前不产生 init，因此以收到 `system/init` 后归一化 alias 核对为准。这些选项是审批模式，不是文件系统沙箱。

DSH 和 Hermes 在任务消息提交前完成应用与核对：失败则阻止本次派工，不会提交任务，也不会以其他权限静默启动。Qoder 的能力与配置校验同样在启动 CLI 前完成；但写入 stdin 后才可能收到 init，若此时回报的权限模式与请求不一致，适配器会立即终止该进程并把任务标记为结果不确定（任务可能已提交），不会自动重放，也不会报告成功。

看板从执行端心跳的 `permission_control` 读取真正可用的原生选项：旧 consumer 没有该字段时只允许跟随默认，并提示更新或重新加载；保存新的显式权限前会校验正在运行的能力。若已保存权限但运行端不支持，新的派工会被明确阻止。DSH 旧心跳只带 `presets` 时仍按旧列表显示；Hermes/Qoder 的选项来自本次适配器发布的能力。

可用模型读取自执行端配置，并显示提供方。Qoder 的模型目录来自真实 `qodercli --list-models`；未安装、未登录、目录读取超时或输出无法识别都会在所选执行端上显示具体原因，不会凭猜测列出模型或思考强度。执行端离线或模型目录读取失败时会提示；已选模型不再可用时保留提示，不静默换模型。思考强度只展示执行端目录为该模型提供的 `efforts`；目录没有强度选项时不虚构选项，界面会禁用并说明跟随模型默认。不选固定模型时也不固定强度，新任务跟随模型默认，不沿用之前的固定强度。目录表示已配置，具体调用仍取决于凭据和上游服务状态。

只想临时调用一次时，保持开关关闭，直接说：

```text
调用 Hermes，在接入时配置的默认任务目录创建 hello.js，输出 Hello, World!。
只修改这个文件，完成后请检查并运行它。
```

### 查看、补充或停止任务

你可以在 Codex 里直接说：

| 目的 | 示例消息 |
|---|---|
| 查进度 | 「查看刚才任务的状态，告诉我当前进度和是否需要我处理。」 |
| 补充要求 | 「继续刚才的任务，补一个边界条件测试，再运行相关测试。」 |
| 请求停止 | 「请求取消刚才的任务，并确认执行端是否已经停止。」 |
| 找到原生聊天 | 「给我刚才任务对应的执行端和原生会话 ID。」 |

关闭自动派工、关闭看板或关闭 Codex 会话，都不会向执行端发送取消指令。Qoder 的取消只对本适配器创建的那个 CLI 子进程发送 SIGINT，等待有限宽限后 SIGKILL；不会影响终端里你自己运行的 `qodercli`，也不会用删除会话冒充归档。需要停止工作时，明确请求取消并检查结果。

### 检查并安装插件更新

看板底部的折叠「插件更新」区可以检查并安装 GitHub 默认分支上的更新。默认关闭 **自动更新**，有新版时手动安装。开启后，看板每天首次打开时检查（多窗口共享 24 小时限制），发现新版便尝试自动安装；有本地改动或运行任务等阻碍时停止本次更新并显示原因。开关保存在本机，关闭不取消已开始的安装。展开区域和 **刷新状态** 只读取本地缓存；手动 **检查更新** 可立即访问已验证的本项目远端。只有安装目录干净、当前分支可快进且没有正在运行的任务时才会执行更新，存在本地改动、分叉、离线或忙碌时会阻止并说明原因。更新不会 stash、reset、强推或删除未跟踪的 SDD 文档，也不会改动任务、模型选择和任务文档。

检查和安装由后台助手执行，看板只在操作后短暂查询状态；若状态查询用尽而更新仍在进行，可随时点击 **刷新状态** 重读本地状态（不会访问远端）。临时连接中断只提示重试，不会把安装显示为失败。若上次依赖或本地插件安装未完成，看板会保留 **安装更新** 的重试入口，重试只补安装，不会重复拉取代码。更新完成后需要重新加载 Codex，或重启 DSH，才能使用新版本；本工程不会自动重启这些应用。

### 自愿发送使用统计

Agents 看板中的「发送匿名使用统计」默认关闭，由你决定是否开启。开启后，共享后台仅在使用插件时，向 `https://stats.helloping.ccwu.cc/v1/usage` 发送随机安装 ID 和插件版本；服务端记录 UTC 日期，用来估算已激活安装数与周活跃安装数。

不上传代码、提示词、项目路径、任务内容或账号。随机 ID 只保存在本机数据目录，更新插件时保留；多个会话共享它。每个 UTC 日最多尝试一次，失败当天不重试，网络超时不会阻塞派工；关闭后停止后续上报。开关独立于自动派工和 SDD，模型无法替你开启。

Cloudflare 作为网络服务提供方仍会处理连接信息。服务端不记录请求正文、IP 或账号，统计数据没有公开读取接口；关闭开关不会撤回已发送的数据。这些指标是参与统计的安装数估计，不等同于真实人数。[服务端与查询说明](services/usage-stats/README.md)。

### 多个会话一起使用

同一数据目录下，派工连接和看板共用一个 **`agents-backend`** 后台。打开多个会话不会各自再启动一套执行后台。

看板隐藏时暂停界面查询，恢复显示后立即更新；任务继续在后台执行。Hermes 与 Qoder 执行模块都在有待处理工作、查询运行时信息或看板读取其模型目录时按需加载；没有对应配置时保持未加载。选择 DSH 不会为模型列表加载 Hermes 或 Qoder。Qoder 空闲时不常驻任何 `qodercli` 子进程，每个工作单使用一个短生命周期的 headless 进程。

在 macOS 活动监视器中搜索 `agents-backend`，即可找到常驻服务；也可运行 `backend status` 查看 PID。实际占用随模块加载和任务数量变化。`agents-hook` 是读取开关或连接认证时的短暂进程。

## 常见问题

### 找不到 Codex 命令怎么办

`enable` 和 `plugin-install` 都支持 `--codex`，用于指定 CLI 可执行文件。若你的 macOS 安装位置与下列路径一致，Hermes 路线可以这样运行：

```bash
node src/command.mjs enable --executor hermes \
  --directory "$HOME/codex-agents-demo" \
  --codex "/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex"

node src/command.mjs plugin-install \
  --codex "/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex"
```

安装位置不同则使用实际路径；DSH 接入命令也可追加同一个 `--codex` 参数。

### 看板已安装，但没有入口或没有自动派工

先查看卡片中的 Hook 状态。若显示「待生效」，按提示在 Codex CLI 的 `/hooks` 审核并信任或启用该 Hook。Hook 已信任后，重新加载旧会话；仍未加载插件时，重启 Codex 或新建会话。看板显示的是本机全局 Hook 配置，不能证明每个旧会话都已加载它。确认开关已开启，执行端也选对了。

### 执行端显示离线怎么办

先确认对应执行端可用：Hermes 在原生界面可以正常聊天；DSH 已打开并加载插件；Qoder 在终端执行 `qodercli --version` 与 `qodercli --list-models` 正常（未登录会明确提示）。看板读取模型目录时会尝试连接所选执行端；也可以让 Codex 检查连接而不提交任务：

```text
检查 Hermes 的连接状态和可用模型目录，不要提交任务。
```

如果仍离线，再查看后台与执行端状态：

```bash
node src/command.mjs backend status
node src/command.mjs status
```

后台在线与执行端在线是两件事。DSH 需要已加载执行插件，Hermes 需要其本机 Dashboard 可连接，Qoder 需要已配置可执行文件且 `--list-models` 可读。

### 任务没有完成时怎么查

先在 Codex 中查看原任务，再打开对应原生聊天，确认是否等待权限、用户输入或模型响应。模型调用超时也可能表现为长时间执行中。

工作单已保存并不代表执行端已经成功完成。若状态为 `uncertain`（待核查），先检查原生记录和实际文件；使用原工作单编号查询，避免重新派发同一份变更。

### 为什么在 Hermes 或 DSH 看不到聊天

让 Codex 提供任务的 `conversation_id`，它是原生会话编号，与工作单编号不同。确认执行端一致，再刷新对话历史；Hermes 侧栏未更新时，可以切换页面后返回工作台。归档的聊天需在对应归档列表中查找。

### 为什么 MCP 里有两个连接

`codex-to-agents` 提供派工工具，插件的 `agents_board` 提供看板和设置工具。它们连接同一个后台，连接条目数不等于常驻进程数。

## 当前范围与验证

当前支持 **DSH 桌面端**、**Hermes Agent CN Desktop** 和 **Qoder CLI**，通过本机工作单保存任务、进度和结果。支持目录、模型选择与同会话追问。DSH 还提供桌面项目注册和聊天列表/改名/归档/恢复；Hermes 提供会话管理；Qoder 使用任务目录与原生会话续聊，没有经过验证的会话列表/改名/归档/恢复能力，这些操作会明确拒绝而不是删除会话冒充归档，也不支持运行中转向。

已核对环境为 macOS、DSH `0.2.1-rc.2`、Hermes CN Desktop `0.6.3` / runtime `0.18.2-cn.2`、Qoder CLI `1.1.78`。2026-10-24 本机完整回归 **259 项自动测试均已通过验证**：主会话单次完整运行 258/259，唯一失败的过期看板静态文案断言（权限默认项改为按执行端动态渲染）修复后定向复跑 1/1 通过（未宣称单次完整运行 259/259）；相关 145 项定向测试通过，日志见 `.local/permissions-main-full-tests.tap`、`.local/permissions-main-panel-recheck.tap`、`.local/permissions-related-tests.tap`，覆盖订单、执行端、看板、更新器、用量统计与三端新会话权限；Qoder 的提交、stream-json 解析、同原生会话续聊、取消、失败/超时/协议错误、登录与目录异常由隔离 CLI 夹具验证，真实 Qoder CLI 已完成 `--permission-mode accept_edits` 新建会话写入文件、以及“只改看板后原会话续聊仍使用原权限”的最小实机验证。Hermes 本轮完成了本机只读协议核对和真实会话级 YOLO 设置与 `session.info` 读回验证（未发送模型编码任务），全局 `config.yaml` 前后 SHA256 一致；Hermes 的完整模型编码任务仍未验收。之前的 Hermes 离线失败记录保留，不作为成功证据；接入状态与模型可用性仍需分别检查。

本工程使用执行端已有的模型配置，不读取模型 API 密钥或账号凭据；Qoder 的可执行路径、版本和模型目录通过普通 CLI 命令确认。文件修改和工具执行仍受执行端权限约束，任务目录提示不能替代权限控制。Qoder 默认不传 `--permission-mode`，沿用原生权限；只有用户在看板明确选择才传对应值，不会自动加 `--yolo` 或跳过确认。Hermes 只有用户明确选择 YOLO 时才写会话级审批旁路，不写全局审批设置。当前不自动选择最优模型、提交或合并代码，也不提供远程多机调度。

## 轻量 SDD 共享工作区

项目下每个任务各留一份 `task.md`，写清**目标、范围、计划和验收条件**。规划较多时，按任务分开更容易查阅，也便于把同一份约定交给不同 Agent。

开启自动派工后，Hook 会要求 SOL 在明确开发任务的方案形成后，先通过 `sdd_task` 保存任务约定，再把保存返回的文档路径交给执行 Agent。仅要求规划时，保存后直接交付；后续调整同一任务时读取并更新原文档。普通问答和讨论不创建任务文档。保存完成以工具回执和实际文件为准。

SDD 任务文档有独立开关，位于看板设置区、始终可见，默认开启（旧配置也按开启处理）。关闭后 Hook 不再要求文档和路径交接，`sdd_task` 拒绝创建、登记和保存，自动派工仍可正常使用。已有文件、目录设置和自动派工开关都会保留；重新开启后恢复编辑。损坏的配置文件按关闭处理，不会默认开启自动写入。

在左侧 Agents 看板展开 SDD 文档区：

1. 设置共享工作区目录，指定 SDD 文档实际存放的位置，默认是 `~/.codex-to-agents/sdd`。
2. 输入名称创建项目分类，再在项目下新建任务，编辑 `task.md` 并保存。
3. 查看 SOL 保存的任务约定，或复制文档路径，在 Codex、DSH、Hermes 或 Qoder 中引用这份文档。

项目按名称分类，每个任务一份文档。默认结构为：

```text
~/.codex-to-agents/sdd/项目编号/
├── project.json
└── 任务编号/
    └── task.md
```

设置的目录用于保存 SDD 任务约定。切换目录后查看新目录中的文档，原目录文件保留。旧版已创建的项目和任务可继续在默认目录中打开。

代码、实现记录和其他文档继续在原项目维护，派工时的工作目录仍指向代码项目。文档区按需读取，不增加后台轮询；另一端修改过文档时，看板会提示冲突并保留未保存的草稿。工作区目录由看板设置，模型文档工具只能在当前选定目录内操作，也不能修改 SDD 开关。关闭 SDD 时，看板禁用文档操作并先保护未保存草稿，目录设置仍可修改。
